# Локальная проверка Yandex Games SDK

## Что используется

Для локальной SDK-среды используется официальный пакет `@yandex-games/sdk-dev-proxy`, закреплённый на версии `0.0.2`. Пакет запускает HTTPS localhost-прокси и отдаёт mock SDK. В dev-режиме он позволяет проверить вызовы SDK без публикации новой версии и без реальных списаний.

В npm-метаданных пакета не указан отдельный публичный GitHub-репозиторий с исходниками. GitHub-проекты вроде [indiesoftby/defold-yagames](https://github.com/indiesoftby/defold-yagames) используют этот же официальный пакет в своих локальных сценариях; источником инструкции и дистрибутива для Filik является [официальная документация Yandex Games](https://yandex.ru/dev/games/doc/ru/concepts/local-launch).

## Запуск mock SDK

Из корня проекта:

`npm run sdk:dev`

Команда:

1. собирает актуальный `dist`;
2. копирует `purchases-catalog.json` только в `dist` для dev-сессии;
3. запускает `@yandex-games/sdk-dev-proxy@0.0.2` на `https://localhost:8080` с `--dev-mode=true`.

Для dev-режима черновик и авторизация не требуются. Браузер может показать предупреждение о локальном сертификате; это ожидаемо для HTTPS localhost. После запуска откройте `https://localhost:8080` и оставьте одну вкладку игры.

## Что проверять в mock SDK

- [ ] Игра загружается через `https://localhost:8080`, а запрос `/sdk.js` получает HTTP 200.
- [ ] В консоли dev-proxy видны вызовы SDK без бесконечных повторов и ошибок ресурсов.
- [ ] Загрузка доходит до интерактивного экрана и вызывает `LoadingAPI.ready()`.
- [ ] Вход на уровень вызывает `GameplayAPI.start()`, меню/модалка/реклама — `stop()`, возврат — повторный `start()`.
- [ ] В dev-proxy открываются mock-авторизация, mock-реклама и callback-ветки success/cancel.
- [ ] В магазине видны все семь записей из `purchases-catalog.json`; цены и валюта берутся из каталога.
- [ ] Покупка, отмена, восстановление и повторная загрузка не выдают одну награду дважды.
- [ ] Данные игрока, покупки и лидерборд переживают reload в localStorage mock SDK.
- [ ] Портретный viewport не имеет горизонтального переполнения.

Локальный mock подтверждает поведение adapter и fallback, но не заменяет staging-проверку настоящих аккаунтов, cloud save, рекламы, покупок и лидерборда на Yandex Games.

## Финальная проверка через draft

После локального mock-прогона собрать архив и запустить официальный proxy без `--dev-mode`:

`npm run release:package`

`npx --yes @yandex-games/sdk-dev-proxy@0.0.2 -p dist --app-id=562137 --port=8080 --csp`

Этот режим требует авторизованный draft приложения `562137` и открывает локальную сборку в реальном Yandex Games окружении. Именно там проверяются production-ветки авторизации, серверных cloud data, реального каталога, рекламных callback и лидерборда. Реальные покупки не выполнять без отдельного согласования и включённого тестового режима.

## Граница production

`purchases-catalog.json` — локальная fixture dev-proxy. `prepare-sdk-dev.mjs` копирует её только после сборки для текущего локального процесса. `check-release.mjs` специально завершает preflight с ошибкой, если файл оказался в `dist`; production ZIP не должен содержать локальный mock-каталог.


## Подтверждённый прогон 2026-09-10

- `@yandex-games/sdk-dev-proxy@0.0.2` запущен на `https://localhost:8080` поверх актуального `dist`.
- `/sdk.js` и `/purchases-catalog.json` отдали HTTP 200; boot и открытие магазина прошли без console/page errors.
- В магазине отобразились 5 coin-pack и 2 permanent offer; success mock purchase зачислил 500 монет, cancel оставил баланс без изменений.
- Rewarded mock выдал 30 монет и одну запись дневного лимита после исчезновения таймера и клика по кресту. До окончания таймера крест закрывает показ без награды; это ожидаемая механика mock SDK.
- После сценариев pending-состояние кнопки снято, рекламный баннер закрыт, ошибок браузера не обнаружено.
