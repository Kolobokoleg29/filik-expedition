# Yandex Games staging checklist

Этот документ — рабочий протокол проверки черновика приложения Filik Expedition перед публикацией. Он разделяет локально доказанные свойства сборки и сценарии, которые можно подтвердить только внутри авторизованного черновика Yandex Games.

## Контекст текущего кандидата

- Приложение: `562137`.
- Кандидат в репозитории: `5.3.4` (`build.json`, `package.json`). Перед загрузкой нужно осознанно решить вопрос о расхождении с версией, отображаемой в кабинете; автоматически подменять версию нельзя.
- Ориентация: портативная/portrait.
- Язык: русский; возрастная маркировка: 0+.
- Cloud saves: включены в черновике и должны быть проверены в аккаунтном сценарии.
- Ключ облачного сохранения: `expedition_rebus_v5`.
- Лидерборд: `expeditionEndless`.
- Платные товары: `expedition_no_ads`, `expedition_starter`, `expedition_coins_500`, `expedition_coins_1200`, `expedition_coins_3000`, `expedition_coins_7500`, `expedition_coins_18000`.
- Известное замечание кабинета `Invalid archive` не является критерием в этом проекте по решению владельца. Сборка всё равно должна пройти локальный `release:package`, а фактическая загрузка архива — отдельный staging-шаг.

## Перед загрузкой

- [ ] Рабочее дерево чистое, проверяемый commit указан в протоколе.
- [ ] Запущен `npm run check:all`; сохранены итоговые числа и версия.
- [ ] Запущен `npm run release:package`.
- [ ] В архиве корнем лежит `index.html`, а не вложенная папка проекта.
- [ ] В архив попали `build.json`, `live-config.json`, `levels.json`, `endless-levels.json` и `assets/UI/app_icon.png`.
- [ ] В архив не попали секреты, токены, локальные dev-hosts, `node_modules`, исходные временные файлы и screenshot-артефакты.
- [ ] Версия архива, `build.json`, `package.json` и запись в staging-протоколе совпадают.

Команды и проверки упаковки не доказывают поведение настоящего SDK. Они доказывают только целостность кандидата и отсутствие известных локальных нарушений.

## Настройки черновика

- [ ] Загружен именно архив текущего commit; в кабинете отображается ожидаемая версия.
- [ ] Включена портретная ориентация; на узком viewport игра не требует горизонтального скролла.
- [ ] Установлены русский язык и 0+; название, описание, инструкция, теги и ключевые слова соответствуют `docs/yandex-draft.json`.
- [ ] Включены cloud saves.
- [ ] Для монетизации заведены все семь ID из `live-config.json`; отображаемая цена берётся из каталога, а не из резервного текста.
- [ ] Создан/включён лидерборд с ID `expeditionEndless`, если он доступен для этого приложения.
- [ ] Черновик сохранён после изменения настроек. Не считать локальный JSON отправкой данных в кабинет.

## Основной маршрут и Loading/Gameplay API

Тестировать в чистом запуске черновика, затем после перезагрузки и возврата со вкладки.

- [ ] До первого интерактивного экрана нет бесконечного loading-state и ошибок ресурсов.
- [ ] `LoadingAPI.ready()` вызывается после готовности интерфейса и данных, не раньше и не многократно.
- [ ] При старте уровня вызывается `GameplayAPI.start()`.
- [ ] При открытии меню, модального окна, паузе, смене вкладки и показе рекламы игровой процесс останавливается.
- [ ] После закрытия модального окна/рекламы и возврата на уровень игра возобновляется ровно один раз.
- [ ] Завершение уровня останавливает gameplay-сессию до показа result modal.
- [ ] При отсутствии SDK игра открывается и позволяет пройти уровень; игрок видит понятное сообщение о локальном режиме.

## Cloud save и аккаунты

Проводить с тестовым аккаунтом и, если возможно, на двух устройствах/профилях. Не использовать в протоколе реальные персональные данные.

- [ ] Новый аккаунт получает пустой cloud state и может начать игру.
- [ ] После прохождения уровня и перезагрузки сохраняются прогресс кампании, монеты, сердца, подсказки, спутник и настройки.
- [ ] После изменения прогресса на устройстве A он появляется на устройстве B после штатной синхронизации.
- [ ] Переход в настройки → синхронизация показывает понятный success или fallback, не зависает навсегда.
- [ ] При таймауте/ошибке cloud API игра продолжает работать локально, а queued save не теряется.
- [ ] При смене аккаунта данные предыдущего аккаунта не показываются новому аккаунту.
- [ ] Повторный запуск после временной недоступности облака не обнуляет локальный прогресс.
- [ ] На `pagehide`, скрытии вкладки и восстановлении сети не возникает дублей или бесконечного цикла сохранений.

## Реклама

Все награды подтверждать только callback-результатом SDK. Закрытие, ошибка, offline и прерванная сессия не должны выдавать награду.

- [ ] Rewarded за монеты выдаёт ровно одну награду только после `onRewarded` и успешного закрытия рекламной сессии.
- [ ] Rewarded за подсказку выдаёт ровно одну бесплатную подсказку; повторный клик во время просмотра заблокирован.
- [ ] Rewarded удвоения награды меняет результат только после успешного просмотра; при ошибке исходная награда остаётся прежней.
- [ ] Дневные лимиты `coinDailyCap=2`, `hintDailyCap=3`, `doubleDailyCap=1` соблюдаются после перезагрузки.
- [ ] Межуровневая реклама не показывается при `adsRemoved` и не показывается раньше двух первых завершённых уровней.
- [ ] Межуровневый cooldown — 180 секунд; повторный быстрый переход не открывает второй показ.
- [ ] Во время рекламы игровой ввод и gameplay API приостановлены; после возврата управление доступно.
- [ ] При offline/SDK error игрок получает понятное сообщение, но уровень и прогресс не блокируются.

## Покупки и восстановление

Проверять только в тестовом режиме кабинета и тестовыми товарами/аккаунтами, если такая возможность доступна. Реальные списания без отдельного подтверждения владельца не выполнять.

- [ ] Каталог загружается из Yandex Games; в карточках показаны фактические цены и валюта.
- [ ] Пока каталог загружается, платные карточки не притворяются доступными; при ошибке есть retry и локальный магазин за игровую валюту.
- [ ] Успешная покупка каждого типа товара обрабатывается один раз.
- [ ] `expedition_no_ads` навсегда отключает межуровневую рекламу.
- [ ] `expedition_starter` один раз выдаёт 300 монет, 3 бесплатные подсказки и спутника Owl; повторная выдача невозможна.
- [ ] Coin pack зачисляет правильный итоговый объём: 500, 1440, 3750, 10125 или 27000 монет.
- [ ] Cancel, timeout, offline и product mismatch не выдают товар; pending-кнопка возвращается в исходное состояние.
- [ ] После успешного receipt сначала подтверждено cloud save, затем выполнен `consumePurchase`; при недоступном cloud receipt остаётся pending для восстановления.
- [ ] После перезагрузки незавершённые покупки восстанавливаются через `getPurchases` и не выдаются повторно.
- [ ] Кнопка «Восстановить покупки» не сообщает об успехе, если восстановлено ноль покупок.

## Лидерборд

- [ ] После результата endless-рекорд отправляется в `expeditionEndless` только при доступном SDK и авторизации.
- [ ] Установка результата не понижает лучший локальный рекорд.
- [ ] Экран показывает реальные entries и текущего игрока, если API их вернул.
- [ ] При недоступном API отображается личный рекорд и объяснение fallback; экран не зависает на бесконечной загрузке.

## Definition of done для staging

Staging считается пройденным только когда все обязательные строки выше имеют результат `PASS`, нет блокирующих ошибок консоли/ресурсов, архив загружен из проверенного commit, а cloud save, реклама, покупки и лидерборд подтверждены настоящим SDK. Локальный mock SDK, зелёный unit/E2E gate и отсутствие реакции на `Invalid archive` не заменяют эти подтверждения.

## Локальный SDK dev-proxy

Перед draft-прогоном использовать `docs/YANDEX_SDK_LOCAL_TESTING.md` и команду `npm run sdk:dev`. Она запускает официальный `@yandex-games/sdk-dev-proxy@0.0.2` в dev-режиме, где mock catalog читается из временной копии `dist/purchases-catalog.json`. Этот режим не доказывает работу настоящей платформы и не должен попадать в production ZIP.


Подтверждённый локальный прогон 2026-09-10: dev-proxy v0.0.2 отдал SDK и каталог с HTTP 200, показал все 7 товаров, purchase success/cancel сохранили ожидаемую идемпотентность, rewarded выдал одну награду после timer + close-cross, console/page errors отсутствовали.
